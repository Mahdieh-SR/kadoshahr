# گیفت‌لند — فروشگاه گیفت‌کارت و اکانت دیجیتال

راهنمای این فایل برای کسی نوشته شده که کد نمی‌نویسد. هرچه لازم است بدانید
اینجا هست.

---

## راه‌اندازی سایت روی کامپیوتر

ترمینال را در پوشه‌ی پروژه باز کنید و بزنید:

```
npm run dev
```

بعد مرورگر را باز کنید: **http://localhost:3000**

برای خاموش کردن، در همان ترمینال `Ctrl + C` بزنید.

> اگر گفت «پورت ۳۰۰۰ اشغال است»، یعنی از قبل روشن است — فقط مرورگر را باز کنید.

---

## ورود به پنل مدیریت

| | |
|---|---|
| آدرس | http://localhost:3000/login |
| شماره ادمین | `09120000000` |

شماره را وارد کنید → **کد تایید در یک کادر بنفش روی همان صفحه نمایش داده
می‌شود** (چون پنل پیامک هنوز وصل نیست) → کد را وارد کنید.

بعد از ورود، دکمه‌ی بنفش **«مدیریت»** بالای صفحه ظاهر می‌شود.

### بخش‌های پنل

| بخش | کارش |
|---|---|
| پیشخوان | خلاصه‌ی وضعیت: سفارش‌های منتظر ارسال، درآمد، موجودی کم |
| سفارش‌ها | فهرست کامل + جستجو + فیلتر وضعیت |
| جزئیات سفارش | **آدرس پستی با دکمه‌ی کپی**، تغییر وضعیت، یادداشت تحویل |
| محصولات | افزودن، ویرایش، قیمت، موجودی، تصاویر |
| کدهای تخفیف | ساخت کد درصدی یا مبلغی با شرایط دلخواه |
| نظرات | تایید یا رد نظر مشتری‌ها + پاسخ دادن |

## کارهای روزمره

### وقتی سفارش جدیدی می‌آید

۱. پنل مدیریت → **سفارش‌ها** → تب **«پرداخت‌شده»**
۲. روی سفارش کلیک کنید → **«کپی آدرس»** را بزنید
۳. بسته را ارسال کنید
۴. وضعیت را روی **«تحویل‌شده»** بگذارید و کد رهگیری پستی را در **یادداشت
تحویل** بنویسید — این متن برای خود مشتری در صفحه‌ی سفارشش نمایش داده می‌شود

### تغییر متن‌های صفحه‌ی اول

فایل `src/content/home.ts` را با Notepad باز کنید. فقط متن **داخل گیومه‌ها**
را عوض کنید و ذخیره کنید. صفحه خودش به‌روز می‌شود.

## دستورهای مفید

| دستور | کارش |
|---|---|
| `npm run dev` | روشن کردن سایت |
| `npm test` | اجرای همه‌ی تست‌های خودکار (۹۸ تست) |
| `npm run limits:reset` | اگر موقع تست پیام «تعداد درخواست بیش از حد» گرفتید |
| `npm run orders:repair` | ترمیم سفارش‌هایی که به دلیل قطعی شبکه ناقص مانده‌اند |
| `npm run db:seed` | پر کردن دوباره‌ی محصولات نمونه ⚠️ محصولات فعلی پاک می‌شوند |
| `npm run db:studio` | دیدن مستقیم محتوای دیتابیس |

## تنظیمات (فایل `.env`)

این فایل رمزها و کلیدهاست. **هرگز جایی منتشرش نکنید** — از قبل طوری تنظیم
شده که به گیت نرود.

| کلید | توضیح |
|---|---|
| `DATABASE_URL` | آدرس دیتابیس (الان: Neon) |
| `AUTH_SECRET` | کلید رمزنگاری ورود — دست نزنید |
| `NEXT_PUBLIC_BASE_URL` | آدرس سایت. موقع انتشار باید دامنه‌ی واقعی شود |
| `ZARINPAL_MODE` | `mock` = درگاه تستی، `live` = درگاه واقعی |
| `ZARINPAL_MERCHANT_ID` | کد ۳۶ کاراکتری از پنل زرین‌پال |
| `SMS_PROVIDER` | `console` = کد روی صفحه، بعداً نام پنل پیامک |

## چک‌لیست قبل از انتشار روی اینترنت

- [ ] دامنه و هاست/سرور تهیه شود (به نام کارفرما)
- [ ] `NEXT_PUBLIC_BASE_URL` روی دامنه‌ی واقعی تنظیم شود
- [ ] `AUTH_SECRET` یک مقدار تصادفی **جدید** بگیرد
- [ ] دیتابیس به پلن پولی یا سرور خودتان منتقل شود (پلن رایگان می‌خوابد و
      بکاپ تضمین‌شده ندارد)
- [ ] پنل پیامک تهیه و در `.env` تنظیم شود
- [ ] مرچنت‌آیدی زرین‌پال گرفته و `ZARINPAL_MODE` روی `live` گذاشته شود
- [ ] شماره‌ی ادمین از `09120000000` به شماره‌ی واقعی تغییر کند
- [ ] محصولات نمونه با محصولات واقعی جایگزین شوند
- [ ] بکاپ خودکار دیتابیس فعال شود

## نکات فنی برای توسعه‌دهنده‌ی بعدی

**استک:** Next.js 16 (App Router) · TypeScript · Tailwind 4 · Prisma 7 ·
PostgreSQL · NextAuth v5

**اصول امنیتی که در کل پروژه رعایت شده:**

- هیچ قیمت، تخفیف یا مبلغی از سمت مرورگر پذیرفته نمی‌شود — همه از دیتابیس
  محاسبه می‌شود (`src/lib/pricing.ts` و `src/lib/discount.ts`)
- تایید پرداخت فقط با درخواست سرور‌به‌سرور به درگاه انجام می‌شود؛ به پارامتر
  `Status` در آدرس بازگشتی هرگز اعتماد نمی‌شود (`src/app/api/payment/verify/`)
- بررسی نقش ادمین داخل خود Server Action هاست، نه فقط در layout صفحه
- محدودیت نرخ درخواست روی همه‌ی مسیرهای حساس (`src/lib/rate-limit.ts`)
- کدهای OTP هش‌شده ذخیره می‌شوند

**مهاجرت دیتابیس:** فایل SQL جدید در `prisma/sql/` بسازید و `npm run
db:migrate` بزنید. (ابزار مهاجرت خود Prisma روی این شبکه به Neon وصل نمی‌شود،
برای همین این مسیر جایگزین ساخته شده است.)

**تست‌ها:** در `scripts/test-*.mjs` — همه با سرور واقعی و دیتابیس واقعی کار
می‌کنند، نه با داده‌ی ساختگی.
